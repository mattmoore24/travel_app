# Samewhere security and cost-safety audit

Started 2026-09-06, on branch `security-hardening`. The app is in TestFlight and has
not shipped to the App Store.

**How to read the severity column.** P0 = data exposure, auth bypass, a leaked secret,
or unbounded cost. P1 = exploitable with effort, or a clear abuse or cost vector.
P2 = hardening. P3 = hygiene.

**Method.** Findings marked _live_ were read from the production database through the
Supabase MCP (`pg_proc`, `pg_namespace`, `pg_policy`, `has_function_privilege`,
`has_schema_privilege`) rather than inferred from the migrations, because in three of
the four most serious cases the finding is a grant that **no migration ever wrote** —
Postgres and the extension defaults wrote them, so reading the repo alone would have
missed every one. Findings marked _repo_ were read from files at the stated line.

## Explicitly not yet assessed

Named so the gaps are visible rather than implied:

- PostHog **event volume** as a billing question (the PII half is done — see
  "What was already right"). Free-tier headroom has not been measured.
- Cloudflare configuration beyond the headers this repo serves (WAF, rate
  limiting, bot rules) — dashboard-side, on `MANUAL_CHECKLIST.md`.

Closed since the first draft: Edge Function input validation (SEC-014 covers
what the headers half of it needed), the client's session storage (already correct —
see "What was already right"), the 18+ server gate (SEC-013), storage bucket
limits (SEC-011), the per-user photo quota (it existed — 25/day, `throttle_photos`; the first pass reported it
missing and that was wrong), the moderation spend ceiling (SEC-010), Edge
Function JWT verification, and rate limits on messages, pins, uploads and
reports (they were all already there — see "What was already right").

Full cost analysis, with the arithmetic and the code it was read from, is in
[`COST_CONTROLS.md`](COST_CONTROLS.md).
