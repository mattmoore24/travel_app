# Samewhere security and cost-safety audit

Started 2026-09-06, on branch `security-hardening`. The app is in TestFlight and has
not shipped to the App Store.

**How to read the severity column.** P0 = data exposure, auth bypass, a leaked secret,
or unbounded cost. P1 = exploitable with effort, or a clear abuse or cost vector.
P2 = hardening. P3 = hygiene.

**Method.** Findings marked _live_ were read from the production database through the
Supabase MCP (`pg_proc`, `pg_namespace`, `pg_policy`, `has_function_privilege`,
`has_schema_privilege`) rather than inferred from the migrations, because in three of
the four most serious cases the finding is a grant that **no migration ever wrote** —
Postgres and the extension defaults wrote them, so reading the repo alone would have
missed every one. Findings marked _repo_ were read from files at the stated line.

## Explicitly not yet assessed

Named so the gaps are visible rather than implied:

- Storage buckets, their MIME/size limits and the per-user photo quota.
- Edge Function JWT verification and input validation.
- The moderation pipeline's spend ceiling — the most likely unbounded cost in the app.
- PostHog event volume and PII in event properties.
- Web security headers, the AASA file, Cloudflare configuration.
- The client's session storage (SecureStore vs AsyncStorage) and the 18+ server gate.
- Rate limits on messages, pins, uploads and reports.
